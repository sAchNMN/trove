# 界面设计规范 v1.0

> 适用：设备归档 Android App（Java，纯代码构建 UI）。
> 规范里的数值都不是"大概"，是可以直接写进代码、也可以用来验收的硬指标。
> 任何一个界面只要违反「第 2 章 容器与文字」「第 4 章 标题层级」，就算功能正确也不算完成。

---

## 0. 一条总原则

**先决定"这一屏最重要的三件事"，再决定字号和位置。**

界面上每一个字号、每一块留白都在回答"这个信息有多重要"。
如果一屏里页面标题、卡片标题、按钮文字、统计数字都是 20sp，那等于告诉用户"所有东西一样重要"——这就是现在这版界面看起来"乱"的根本原因，而不是颜色没调好。

---

## 1. 字号与排版角色表

字号不是"大小"，是"角色"。一个字号只能承担一个角色。

| 角色 | 字号 | 字重 | 用在哪 | 禁止 |
| --- | --- | --- | --- | --- |
| 页面标题 | 20sp | 700 | 每屏**仅 1 个**，如「文件移动分类」 | 不得有同字号的第二个标题 |
| 卡片标题 | 16sp | 700 | 「分类策略」「媒体索引」等卡片头 | 不得与页面标题同字号 |
| 列表主文本 | 16sp | 500 | 目录名、工具名 | 不得 20sp |
| 正文 / 按钮 | 14sp | 400/500 | 说明段、按钮文字、选项 | 不得小于 14sp 用于句子 |
| 辅助说明 | 13sp | 400 | 一句话解释、副标题 | 不得当作标题用 |
| 元数据 / 状态 | 12sp | 400 | 路径、文件数、时间、状态行 | 不得用于需要阅读的句子 |
| 标签 / 徽章 | 11sp | 700 | 只有 `01` `02` 这类数字或英文标签 | 不得用于中文句子 |

补充规则：

- **中文句子的字号下限是 14sp**；12–13sp 只能放短语、数字、路径。
- **任何正文都不允许 28sp**。28sp 只保留给"统计数字"（照片/视频/待确认的计数），且同一屏最多出现 3 个。
- 相邻两级字号至少差 2sp，并且**字重必须不同**（20/700 与 16/700 可以共存，16/700 与 16/400 也可以，但 20/700 与 20/700 不行）。
- 行高统一 `setLineSpacing(0, 1.45f)`；标题 1.2；不要用 `includeFontPadding=true` 的默认值去凑间距。
- 全 App 只允许上面 7 个字号。代码里出现第 8 个字号 = 违规。

## 2. 容器与文字（当前最严重的系统性问题）

**文字决定容器，不是容器决定文字。**

现在的代码里有大量 `new LinearLayout.LayoutParams(-1, dp(48))` 配长文案，这必然导致两种结果：要么文字换行被裁掉下半行，要么文字被截成"授权整个 / Pictu…"，要么为了塞进去把字号改小。三条都是错的。

### 2.1 高度

- 任何包含**可能换行文本**的容器，高度写 `wrap_content`，用 `setMinHeight()` 保证最小高度。
- 只有**标签确定是单行且长度可控**（如"确定""取消""下一步"）时，才允许写死高度。
- 主按钮 52dp、次按钮 48dp、图标按钮 48×48：这是**最小高度**，不是固定高度。

### 2.2 宽度与并排

- 并排两个按钮时，任一按钮文案超过 6 个汉字（或含英文单词）→ **改为竖排**，不要平分宽度。
  反例：`授权整个 DCIM` / `授权整个 Pictures` 平分屏宽 → 第二个必然换行被裁。
- 列表行内的标题区一律 `layout_weight=1` + `wrap_content` 高度，右侧图标固定 48dp。
- 不要用 `0dp + weight` 去分一个长度未知的文本区；要么给足宽度，要么让它自己换行。

### 2.3 截断

| 内容 | 允许省略吗 | 规则 |
| --- | --- | --- |
| 页面标题、卡片标题、按钮文字 | ❌ 永不 | 改布局或改文案 |
| 单行状态摘要 | ✅ | `maxLines=2` + `ellipsize=END`，整行可点开详情 |
| 文件路径、目录名 | ✅ | 2 行后省略，点击查看完整路径 |
| 列表主文本 | ⚠️ 尽量不 | 最多 2 行 |

- 省略号只出现在**右边缘**，不允许中间截断。
- 被省略的内容必须有一个"点开看全文"的入口，否则就是信息丢失。

### 2.4 长文案的三种正确解法（按优先级）

1. **缩短文案**：`打开全部照片 / 视频（含 Download）` → `浏览全部媒体`，实现细节移到说明里。
2. **改变排布**：并排改竖排；一行改"标题 + 副标题"两行。
3. **允许变高**：`wrap_content`，卡片跟着长高。

**永远不用第 4 种：缩小字号。**

## 3. 间距、圆角、颜色

- 间距只用 4 / 8 / 12 / 16 / 24 / 32（已有 `Ui.S1..S6`）。
- 页面左右内边距 16；卡片内边距 16；卡片之间 16；卡片内段落之间 12；标题与内容之间 8。
- 圆角：控件 12、卡片 16、药丸 28（已有 `Ui.R_*`），不要出现第二个 14 或 18。
- 一屏**只有一个实心深色主按钮**。其余按钮：1px 描边（`quietButton`）或纯文字。
- 不允许用颜色表达状态（红/绿）；用文案 + 图标 + 字重。深浅对比靠 `INK / MUTED / FAINT` 三级。

---

## 4. 标题层级

一屏只允许出现：

```
[页面标题 20sp]                    [1 个主要操作图标]
[一行 13sp 状态/范围说明]
---
卡片标题 16sp
正文 14sp
```

明确禁止：

- 页面标题上方再放一个 11sp 的 `整理 · 本地文件` 之类 overline。它和标题说的是同一件事，纯属重复。
  面包屑只在"三级以上导航"时出现，且必须在返回箭头旁边，不能悬在标题上方。
- 页面标题和第一张卡的卡片标题写同一个词（现在「文件移动分类」出现两次）。
- 分步页的 `01 选择整理目录` 与页面标题之间再插一个说明块。步骤徽章属于内容，不属于页头。

## 5. 文案规则

**界面文案回答"我现在能做什么、会发生什么"，不回答"这个功能是怎么实现的"。**

| ❌ 现在界面上的写法 | ✅ 应该写成 |
| --- | --- |
| 单页模式 · 从上到下完成设置 | 直接删掉（这是给开发者的需求描述） |
| 手动扫描补充目录 / 使用"扫描全部照片 / 视频"时不需要再点这里 | `补充目录` + 按钮 `扫描这些目录` |
| 打开全部照片 / 视频（含 Download） | `浏览全部媒体` |
| 系统没有索引的目录，可以在这里授权；授权后点"扫描设备"递归扫描 | `系统相册找不到的文件夹，可在这里添加` |
| 扫描完成 · 0 个媒体文件 · 0 个已识别 · 0 个非媒体文件未处理 | `没有读到文件` + 一行原因 + 一个「重新授权」按钮 |

其他文案要求：

- 按钮 = 动词 + 对象，≤ 8 个汉字：`开始整理`、`扫描这些目录`、`重新授权`。
- 不用"未完成：xxx"这种开发者措辞；错误 = 原因 + 下一步。
- 数字与单位之间不留空格：`12.5 MB`、`0 个文件` 保持统一即可，但同一屏只能有一种写法。
- 不使用感叹号、不使用"请注意"。

## 6. 状态：空 / 加载 / 失败 / 部分成功

四种状态必须视觉可区分，不能都用一行灰字。

- **空**：一句原因 + 一个动作按钮。例：`这个文件夹里没有可整理的媒体` + `换一个文件夹`。
- **加载**：进度条 + 当前动作（`正在读取 128 / 430`），超过 400ms 才显示，避免闪烁。
- **失败**：说明哪一步失败 + 下一步按钮（`重新授权` / `重试`）。
- **部分成功**：明确"成功 N 个，失败 M 个，原因…"，并提供"查看失败项"。

**0 条结果禁止显示"完成"。** 0 是"空"或"失败"，不是"完成"。

## 7. 底部导航与安全区

- 导航条高度 64dp，图标 22dp，文字 11sp，选中态用**浅底 + 图标着色**，不要整块黑色药丸（现在 88×60 的纯黑块把内容压住了）。
- **导航的显隐只跟随手指，不跟随时间**：
  - 向下滚动 → 收起（180ms，向下位移 + 淡出）；
  - 停手不滚动 → **保持收起**，不许定时自动浮现；
  - 向上滚动 → 出现（220ms，淡入 + 复位）；
  - 滚动到顶部且导航处于收起状态 → 立即出现。
  理由：自动浮现的导航条会在用户准备点内容时挡住目标，这是可以避免的误触。
- 内容区 `paddingBottom = 导航高度 + 24dp + 系统手势区`，滚动到底时最后一张卡必须完整可见。
- 滚动时隐藏导航是加分项，但**隐藏动画不得让内容跳动**。

### 7.1 常驻操作条（分步模式的「上一步 / 下一步」）

- 常驻操作条必须**参与布局**（作为页面纵向排列的最后一块），不能浮在滚动内容之上——浮层会正好盖住来源列表、「扫描这些目录」这类首要入口。
- 操作条的底部留白只用来避让导航条；导航条隐藏时也不要把内容让出两倍空间。
- 按钮高度 `wrap_content` + `minHeight`，文案短到半宽下 fontScale 1.3 仍是一行：`上一步 / 下一步`，不要写「下一步：分类预览」这种把下一步标题塞进按钮的写法。下一步是什么由步骤标题回答。

### 7.2 标题下的状态行

- 最多 2 行，`ellipsize=END`，点开看全文。
- 一行只放用户要的数字（待整理 / 已归档跳过 / 用时），实现细节（缓存复用、索引范围）放到别处。
- 状态行不要用「圆点 View + 文本」的横向组合：文本测量成一行时圆点会把可用宽度再压窄，长句直接溢出被裁。用 `● ` 前缀或独立一行更稳。

---

## 8. 深色模式与无障碍

- 正文对比度 ≥ 4.5:1；`FAINT` 只能用于装饰。
- `fontScale = 1.3` 时不得出现任何裁切；必须实测。
- 所有图标按钮有 `contentDescription`；所有可点区域 ≥ 48×48。
- 320dp 宽度（小屏）下，所有并排布局要么换行要么竖排。

## 9. 验收清单（改完必须逐条回答）

对**每一个改动过的屏幕**回答：

1. 这一屏有几个页面标题？（必须 = 1）
2. 出现了几种字号？分别是哪些角色？（必须 ≤ 5 种，且都在第 1 章表里）
3. 有几个 `?` 入口？（必须 ≤ 2）
4. 有几个实心主按钮？（必须 = 1）
5. 有没有固定高度 + 可能换行文字的容器？（必须 = 0）
6. 有没有被省略的标题或按钮文字？（必须 = 0）
7. 320dp 宽 + fontScale 1.3 + 深色模式下，截图是否完整无裁切？
8. 空数据时显示什么？有没有动作入口？
9. 长目录名（> 30 字）时，路径显示几行？能否看到全文？
10. 底部导航是否遮挡最后一张卡片？
11. 常驻操作条（如果有）是否参与布局、不遮挡任何可点内容？
12. 状态行长句是否真的换行（不是被裁成一行）？

回答方式：一张表，逐条写"改前 / 改后"，附截图。
